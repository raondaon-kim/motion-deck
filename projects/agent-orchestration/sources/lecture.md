AI 에이전트 오케스트레이션: 팀 구성과 검수 순환

1. 왜 팀인가
단일 에이전트는 맥락이 길어질수록 품질이 떨어집니다. 역할을 나누면 각 에이전트가 좁은 맥락 안에서 더 정확하게 일합니다.

2. 기본 구성

오케스트레이터: 목표를 작업 단위로 쪼개고, 배정하고, 결과를 통합합니다.
작업자: 리서치, 작성, 코딩처럼 한 가지 역할만 맡습니다.
검수자: 결과를 기준표로 평가하고 통과 또는 반려를 판정합니다.

3. 검수 순환 루프
계획 → 실행 → 검수 → (반려 시) 피드백 반영 후 재작업 → 통과 → 통합

핵심은 검수자가 무엇이 왜 틀렸는지를 구체적으로 돌려주는 것입니다. "개선하라" 같은 막연한 피드백은 루프를 헛돌게 만듭니다.

4. 설계 원칙

작업자와 검수자를 분리합니다. 자기 결과를 스스로 검수하면 관대해집니다.
기준은 미리 명문화합니다. 체크리스트, 테스트, 출력 스키마 등을 활용합니다.
반복 상한을 둡니다. 보통 2~3회로 정하고, 넘기면 사람에게 넘깁니다.
상태는 파일로 공유합니다. 작업 기록이 남아야 추적과 재시작이 가능합니다.

5. 흔한 실패

역할을 너무 잘게 나눠 에이전트 간 통신 비용이 커집니다.
검수 기준이 없어 루프가 끝나지 않습니다.
오케스트레이터가 직접 작업까지 떠안아 병목이 됩니다.
